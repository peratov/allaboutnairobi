{# The newsletter sign-up. Three shapes: * with NEWSLETTER_LIVE, the site's own list (api/news.mjs). A plain form POST to /api/news?r=subscribe, answered with a redirect to /newsletter/check, so it works with scripts off; newsletter.mjs turns it into a request that answers in place. The source is the page it was on, which is how the admin can say which pages bring readers in. `website` is a honeypot: hidden from people, filled in by bots, and a sign-up carrying it is answered and ignored. * failing that, with NEWSLETTER_ACTION, a real form that posts straight to whichever provider runs the list. No JavaScript, no fetch - a plain form POST works with scripts off and does not need connect-src widening in the CSP. * failing that, a mailto: link. Not a placeholder: for a list of a few hundred readers it is a genuine answer, and it means this page is never broken while a provider is being chosen.
